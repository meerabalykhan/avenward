An environment-blocked check is not represented as passing. These commands must
be run in the owner's normal PowerShell before the foundation is signed off:

```powershell
Copy-Item .env.example .env
docker compose config --quiet
docker compose up --build -d
Invoke-RestMethod http://localhost:8000/api/v1/health
Invoke-RestMethod http://localhost:8000/api/v1/ready
```

Expected health response: `status` is `ok`. Expected readiness response after all
containers are healthy: `status` is `ready`, with PostgreSQL and Redis both
`available`. The browser shell should load at <http://localhost:8080>.

Then run the container-independent checks from containers or a direct developer
environment. CI is configured to run them on the first GitHub pull request.

On Windows, the complete containerized validation command is:

```powershell
.\scripts\windows\dev.ps1 check
```

## Security review notes

- No `.env` file or real data is present.
- Only loopback host ports are published by Compose.
- PostgreSQL and Redis are confined to the internal Docker network.
- Nginx includes a restrictive initial content security policy and basic browser
  hardening headers.
- Readiness errors collapse to `unavailable` and do not reveal connection details.
- The example database password is a documented local placeholder, not a secret.
- Public deployment and real data remain explicitly unsupported.
